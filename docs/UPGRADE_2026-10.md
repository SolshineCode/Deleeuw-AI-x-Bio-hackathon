# BioRefusalAudit: master change list (opened 2026-10-22)

This is the register of everything in arXiv:2605.30162v1 and in this repository that has to
change, why, the evidence, and the fix. It is additive: entries are never deleted. When an
item is done, its **Status** cell gets a dated note and a commit hash. When an entry turns out
to be wrong, a dated correction is added under it.

Conventions:

- `tex:NNN` = line in `paper/submission_final.tex` (identical to the arXiv v1 source).
- Items are referred to by ID. Tier-3 prompts and tier-3 model outputs are never quoted
  here, in commit messages, or in any public file; tier-3 items are named by ID only.
- "Placeholder" means a record whose `surface_label` is `refuse` and whose `surface_soft` is
  exactly uniform (0.2 on each class). `results/_audit_2026-10/placeholder_audit.{md,json}`
  lists every one by run and ID (generated by `scripts/audit_judge_placeholders.py`).
- Status values: `open`, `done YYYY-MM-DD (<commit>)`, `blocked: <who/what>`.

Contents:

## 1. Root causes

| ID | Cause | Evidence | Fix |
|---|---|---|---|
| R1 | `aggregate_votes` returns `label="refuse"` with a uniform soft distribution when the weighted tally is zero (no usable vote). The paper's tables count these as refusals. | `biorefusalaudit/judges/consortium.py:63-72` (pre-fix). 1,172 of 1,283 `refuse` labels in committed reports are this placeholder. | Explicit `unjudged` state that never maps to a surface class; excluded from rates and counted. Done on branch `fix/2026-10-judge-unjudged` (see §5). |
| R2 | The regex first pass is turned into a vote even when it matches nothing: `_regex_as_vote` emits `refuse` at confidence 0. LLM judges are off by default (`--use-llm-judges` defaults to `False`), and every LLM judge adapter also emits `refuse` at confidence 0 on any error. With no LLM vote, every completion the regex cannot match becomes a placeholder `refuse`. | `biorefusalaudit/runner/eval_runner.py:51-59`; `biorefusalaudit/cli.py:36`; `biorefusalaudit/judges/llm_judges.py:81,85,98-105,129-134`. In every committed real run, each record's soft distribution is either exactly one-hot or exactly uniform; no run has a mixed distribution. That pattern is what a single regex voter produces, and it is very unlikely if three LLM judges had voted on 3,000+ records. No report records which judges ran. | Same branch: regex "no match" becomes an abstention, LLM-judge errors become abstentions, and each record stores its votes and judge list. Paper must describe the judge as it actually ran (regex only, as far as the data show). |
| R3 | `scripts/rejudge_stored_completions.py` (used for the "corrected" Gemma 2 numbers) ran `regex_classify` on stored completions. Tier-3 completions are stored as the redaction string, so the regex saw `[REDACTED — ...]`, found nothing, and the script's fallback wrote `hedge` at confidence 0.4. | `regex_classify(REDACTED_PLACEHOLDER).label is None`; `rejudge_stored_completions.py:41-46`. In `gemma-2-2b-it-L12-tuned-rejudged`, all 22 hazard-tier labels are `hedge` at confidence 0.4 on redacted text; all 35 hedges in the run are the fallback. The script's `_was_degenerate` flag is computed after `surface_soft` is overwritten, so it is always `false`. | Re-judge must skip redacted records (mark `unjudged: redacted`) and must not convert "no match" into a class. Superseded by `scripts/relabel_openrouter_free.py` on the fix branch. |
| R4 | D is a function of the surface soft vector `s`. For placeholder records `s` is uniform, so D for those records measures the placeholder, not the model. The re-judge kept the original D. | `eval_runner.py:103-106`; `_rejudge_note` in the re-judged reports ("original run activations/D-values unchanged"). | Recompute D from stored `feature_vec` with the new labels, and report D only for judged records. |
| R5 | `scripts/format_ablation.py::_quick_classify` returns `comply` when nothing matches. | `scripts/format_ablation.py:68-83`. | Same treatment as R2: "no match" is `unjudged`. Re-judge the stored previews (non-tier-3 only). |
| R6 | Judge votes, `flagged_for_review`, seeds, library versions, model revisions and SAE checkpoint hashes are not stored in `report.json`. | `biorefusalaudit/reporting/report.py` `PromptRecord` fields. | Add `judge_votes`, `judge_status`, `judges_run` to records; add a run-metadata block. Votes done on the fix branch; run metadata open. |
| R7 | Tier-3 completions are redacted at write time, so no tier-3 behavioural label can be checked by anyone, including the author. | `reporting/report.py:99`, `reporting/redaction.py`. | Keep redaction for public files, but write an unredacted private copy (hashed, never committed) on future runs so tier-3 labels can be audited. Needs new generation runs (GPU, Caleb's call). |

### 4.2 What a history purge would involve (not done; Caleb decides)

can still read them through old commits, the 10 branches listed below, GitHub's commit and
blob URLs, and any existing clone. A purge means:

   format-ablation previews (D-3) are in older versions of four `report.json` files; purging
   those needs `--replace-text` or a blob replacement, not a path filter. Branches holding
   the files at their tip: `main` (until the cleanup merge), `arxiv-revision`,
   `feature/hf-publish-pipeline`, `fix/arxiv-correct-source-build`,
   `paper/fix-geometric-intuition-accuracy`, `paper/geometric-intuition-subsection`,
   `paper/geometric-intuition-v3`, `paper/rename-intuition-heading`,
   `paper/rewrite-geometric-intuition`, `paper/structural-additions-hl3-bio-sae`,
